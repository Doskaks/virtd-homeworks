## Задача 2

Выберите один из вариантов платформы в зависимости от задачи. Здесь нет однозначно верного ответа так как все зависит от конкретных условий: финансирование, компетенции специалистов, удобство использования, надежность, требования ИБ и законодательства, фазы луны.

Тип платформы:

- физические сервера;
- паравиртуализация;
- виртуализация уровня ОС;

Задачи:

- высоконагруженная база данных MySql, критичная к отказу;
- различные web-приложения;
- Windows-системы для использования бухгалтерским отделом;
- системы, выполняющие высокопроизводительные расчёты на GPU.

Объясните критерии выбора платформы в каждом случае.

## Решение 2

1. Высоконагруженная MySQL, критичная к отказу

Платформа: Физические сервера (bare-metal)

Почему:

    Минимальные накладные расходы — нет прослойки гипервизора, что критично для производительности БД
    Предсказуемость ресурсов — никакого «шума соседей»
    Отказоустойчивость достигается кластеризацией (репликация) на физическом уровне
    Прямой доступ к дискам (NVMe/SSD) без прослойки виртуализации

2. Различные web-приложения

Платформа: Виртуализация уровня ОС (контейнеры, Docker)

Почему:

    Быстрое развёртывание и масштабирование
    Изоляция приложений друг от друга
    Экономия ресурсов — множество контейнеров на одном хосте
    Удобство CI/CD и микросервисной архитектуры

3. Windows-системы для бухгалтерии

Платформа: Паравиртуализация (KVM, Hyper-V, VMware)

Почему:

    Нужна полноценная гостевая ОС с GUI (графическим интерфейсом)
    Паравиртуализация даёт хорошую производительность и совместимость с Windows
    Возможность делать снапшоты (бэкапы) перед обновлениями 1С/бухгалтерии
    Удобное управление жизненным циклом ВМ

4. Высокопроизводительные расчёты на GPU

Платформа: Физические сервера (bare-metal с GPU)

Почему:

    Прямой доступ к GPU — виртуализация добавляет задержки и снижает производительность
    Поддержка GPU-пассажиров (vGPU) есть, но для максимальной производительности лучше "голое железо"
    Высокое энергопотребление и тепловыделение проще контролировать на физическом уровне
    Для HPC-кластеров критична минимальная задержка и максимальная пропускная способность



## Задача 3

Выберите подходящую систему управления виртуализацией для предложенного сценария. Опишите ваш выбор.

Сценарии:

1. 100 виртуальных машин на базе Linux и Windows, общие задачи, нет особых требований. Преимущественно Windows based-инфраструктура, требуется реализация программных балансировщиков нагрузки, репликации данных и автоматизированного механизма создания резервных копий.
2. Требуется наиболее производительное бесплатное open source-решение для виртуализации небольшой (20-30 серверов) инфраструктуры на базе Linux и Windows виртуальных машин.
3. Необходимо бесплатное, максимально совместимое и производительное решение для виртуализации Windows-инфраструктуры.
4. Необходимо рабочее окружение для тестирования программного продукта на нескольких дистрибутивах Linux.


## Решение 3

1. Крупная инфраструктура (100 ВМ, Windows, балансировка, бэкапы)

Решение: Microsoft Hyper-V (в составе Windows Server)
Или: VMware vSphere (если бюджет позволяет)

Почему:

    Нативная поддержка Windows-гостевых ОС (максимальная производительность)
    Встроенные механизмы репликации (Hyper-V Replica)
    Интеграция с Windows-балансировщиками (NLB) и средствами бэкапа (Windows Server Backup, VSS)
    Централизованное управление (SCVMM или Failover Cluster Manager)

2. Производительное open source (20-30 серверов, Linux/Windows)

Решение: KVM (Kernel-based Virtual Machine) + Proxmox VE (надстройка для управления)

Почему:

    KVM — самое производительное open source-решение (нативная виртуализация)
    Proxmox даёт веб-интерфейс, управление хранилищами, миграцию, бэкапы
    Поддерживает и Linux, и Windows (с установкой драйверов virtio)
    Полностью бесплатно (с опциональной платной поддержкой)

3. Бесплатное и совместимое с Windows

Решение: Microsoft Hyper-V Server (бесплатная версия)

Почему:

    Это бесплатный продукт Microsoft (отдельная редакция)
    Максимальная совместимость с Windows-гостевыми ОС
    Поддержка всех современных версий Windows Server и клиентских Windows
    Есть возможность централизованного управления через RSAT

4. Тестирование на нескольких дистрибутивах Linux

Решение: Docker (контейнеры) или VirtualBox (ВМ)

Почему:

    Docker — если тестируются приложения, а не ядро/системные сервисы (легковесность, скорость)
    VirtualBox — если нужно тестировать разные дистрибутивы с GUI или ядерные компоненты
    Оба решения бесплатны и просты в установке на рабочей станции
    Для CLI-серверов можно использовать также Multipass (от Canonical)


## Задача 4

Опишите возможные проблемы и недостатки гетерогенной среды виртуализации (использования нескольких систем управления виртуализацией одновременно) и что необходимо сделать для минимизации этих рисков и проблем. Если бы у вас был выбор, создавали бы вы гетерогенную среду или нет?


## Решение 4

Основные проблемы гетерогенной среды:

    Сложность управления — разные интерфейсы, API, инструменты мониторинга
    Рост затрат — лицензии, обучение персонала, поддержка разных вендоров
    Несовместимость инструментов — бэкапы, балансировка, миграция между платформами
    Квалификация команды — нужно знать несколько стеков технологий
    Усложнение аварийного восстановления — разные снапшоты, форматы дисков

Минимизация рисков:

    Внедрение единой панели управления (например, через API или облачные платформы)
    Стандартизация форматов образов (OVF/OVA где возможно)
    Централизованное хранилище (SAN/NAS) для унификации работы с данными
    Автоматизация через инфраструктуру как код (Terraform, Ansible)
    Чёткое разделение зон ответственности и нагрузки по платформам

Мой выбор:

Нет, не стал бы создавать гетерогенную среду намеренно.

Лучше выбрать одну основную платформу (KVM/Proxmox или Hyper-V) под 90% задач, а вторую использовать только если есть жёсткие требования (например, специфическое ПО, работающее только на VMware). Гетерогенность — всегда компромисс, оправданный только бизнес-необходимостью, а не «техническим разнообразием».
